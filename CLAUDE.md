# Drawing Viewer

Offline, browser-only viewer for engineering drawings (CALS raster, TIFF, DXF, DWG). Rust decodes and
renders to WASM; a small TypeScript front end draws to a canvas. The build is one self-contained HTML file.

See `README.md` for supported formats, toolchain setup, and project layout.

## Commands

```sh
npm run build   # WASM + typecheck + dist/index.html — run this to verify a change
npm run dev     # WASM + Vite dev server
cargo test      # Rust unit tests
```

`npm run build` is what CI runs (after `cargo test`). Both must pass.

## Hard constraints

- **No network access, ever.** The built page has a CSP of `default-src 'none'` (`vite.config.ts`).
  Do not add fetches, CDN links, web fonts, or runtime-loaded assets. Everything is inlined.
- **Single file output.** WASM is embedded via the `?base64` import; keep it that way.
- **`wasm-bindgen-cli` must match the `wasm-bindgen` version in `Cargo.lock`.** Bumping the crate
  means bumping the CLI locally too (CI reads the version from the lockfile).

## Architecture notes

- Decoding lives in Rust (`crates/raster`). Raster rendering is Rust too; TypeScript does not touch
  pixels. Vector formats (DXF, DWG) are parsed and expanded in Rust, then stroked by TS with Canvas 2D
  (`VectorDocument` in `types.ts`); TS never parses file contents.
- `web/pkg/` is generated by `npm run build:wasm` — never edit it.
- New formats are `FormatPlugin`s (`web/src/formats/types.ts`) registered in `web/src/main.ts`.
  Raster formats reuse the WASM adapter in `web/src/formats/wasm.ts`.
- WASM memory can grow during `render()`; create typed-array views on `wasm.memory.buffer` only
  after the call returns (see `wasm.ts`).

## Workflow

- Work on `dev`; PRs go `dev` → `main`. Pushing to `main` deploys to GitHub Pages.
- Test files go in `./samples/` (git-ignored). Generate a synthetic one with the `make_sample`
  example from the README.
